# VkusVill Smart Cart — Оптимизация и рефакторинг

## TL;DR

Скилл для «умной корзины» ВкусВилла переписан с трёх-stage matching-пайплайном (substring → Levenshtein → character trigram cosine). LLM больше не читает prefs-файл в контекст и не «рассуждает» над матчингом — вся механическая работа вынесена в `execute_code` (Python). Результат: **экономия токенов**, 0 внешних зависимостей, 7/8 на тестовом наборе.

---

## 1. Проблема (что было)

### Старая архитектура (v1)

```
Пользователь: «добавь молоко»
        │
        ▼
LLM читает vkusvill_prefs.json (весь файл в контекст)
        │
LLM «рассуждает» над двухпроходным матчингом
        │
LLM вызывает MCP vkusvill_products_search или vkusvill_cart_link_create
```

**Проблемы:**

1. **Токены.** Каждый запрос — весь `vkusvill_prefs.json` грузится в контекст LLM. С 10+ товарами и несколькими ключами на каждый это десятки строк JSON, плюс системный промпт на «рассуждение» над матчингом.

2. **LLM делает детерминированную работу.** Сравнение строк (подстрока, расстояние Левенштейна) — чисто алгоритмическая задача, нейросеть для неё избыточна.

3. **MCP возвращает жирные ответы.** `vkusvill_products_search` отдаёт полные карточки товаров с фото, составом, КБЖУ — всё это попадает в контекст, даже если пользователю нужно только название и цена.

4. **Ограниченный матчинг.** Только substring. Без обработки опечаток, транслита, перестановок слов.

---

## 2. Решение (v2)

### Новая архитектура

```
Пользователь: «добавь нарзaн»
        │
        ▼
LLM вызывает execute_code → Python делает ВСЁ:
  1. Читает vkusvill_prefs.json (локально, вне LLM-контекста)
  2. Прогоняет три этапа матчинга
  3. Возвращает компактный результат
        │
        ▼
LLM получает: {"stage": "levenshtein", "xml_id": 56160, "name": "Нарзан", "distance": 0.167}
        │
LLM формирует ответ: «Беру: Нарзан — похоже на "нарзaн" (расстояние 0.17)»
        │
LLM вызывает MCP vkusvill_cart_link_create
```

**Ключевой принцип:** всё детерминированное — в Python. LLM остаётся только диалог и принятие решений.

### Экономия токенов

| Операция | До (v1) | После (v2) |
|---|---|---|
| Чтение prefs | Весь JSON в контекст LLM | Локально в Python |
| Матчинг | LLM «рассуждает» (сотни токенов) | Python (0 токенов) |
| Результат матчинга | Полный ответ MCP с фото/КБЖУ | Одна строка JSON |
| **Итого на запрос** | ~500-2000 токенов | ~50-100 токенов |

## 3. Три этапа матчинга

### Этап 1: Substring (два прохода)

**Метод:** поиск подстроки. Порог: нет (детерминированный).

**Проход 1 — ключ как подстрока запроса:**

```python
# "добавь молоко" → ключ "молоко" является подстрокой → матч
# "творожная запеканка" → ключ "запеканка" является подстрокой → матч
if key.lower() in user_text: return match
```

**Проход 2 — слово запроса как подстрока ключа:**

```python
# "сок" → слово "сок" внутри ключа "морковный сок" → матч
# "запеканк" → слово "запеканк" внутри ключа "запеканка" → матч
```

При нескольких матчах выбирается ключ с **наибольшим количеством совпавших слов** (при равенстве — самый длинный).

**Что ловит:** точные совпадения, частичные слова, слово-внутри-ключа.

### Этап 2: Levenshtein (нормализованный, по словам)

**Метод:** Wagner-Fischer edit distance. Каждое слово запроса сравнивается с каждым словом каждого ключа. Порог: ≤ 0.25.

```python
norm_dist = levenshtein(query_word, key_word) / max(len(query_word), len(key_word))
```

**Что ловит:**

| Запрос | Ключ | dist | norm | Результат |
|---|---|---|---|---|
| `нарзaн` | `нарзан` | 1/6 | 0.167 | ✓ матч |
| `ёгурт` | `йогурт` | 1/6 | 0.167 | ✓ матч |
| `кефир` | `нарзан` | 5/6 | 0.833 | ✗ мимо |
| `нaрзaн` (2 лат.) | `нарзан` | 2/6 | 0.333 | ✗ мимо (граничный) |

**Почему по словам, а не по всей строке:**
- `«положи нарзaн 2 шт»` → слово `нарзaн` матчится с ключом `нарзан` (0.167)
- Если сравнивать всю строку: `«положи нарзaн 2 шт»` vs `«нарзан»` → расстояние ~15, мимо

### Этап 3: Character trigram cosine

**Метод:** извлечение символьных триграмм с padding (пробелы по краям), построение TF-векторов, косинусное расстояние. Порог: ≥ 0.75.

```python
def char_trigrams(s):
    s = "  " + s.lower() + " "   # padding
    return {s[i:i+3]: count for i in range(len(s)-2)}

def trigram_cosine(a, b):
    dot = sum(a[k] * b.get(k, 0) for k in shared_keys)
    return dot / (norm(a) * norm(b))
```

**Пример: `«творожная запеканка»` ↔ `«запеканка творожная»`**

```
Триграммы первой:  тв, тво, вор, оро, рож, ожн, жна, ная, ая , я з,  за, зап, апе, пек, ека, кан, анк, нка, ка 
Триграммы второй:   з,  за, зап, апе, пек, ека, кан, анк, нка, ка , а т,  тв, тво, вор, оро, рож, ожн, жна, ная, ая 

Общих: 18 из 20 → cosine = 0.900 → матч ✓
```

**Что ловит:** перестановки слов, которые substring пропустил бы без нужного ключа.

**Что НЕ ловит:** семантические совпадения (`«вода минеральная»` → `«Нарзан»`). Для этого нужны настоящие эмбеддинги (sentence-transformers), которые не устанавливаются на aarch64/Android без сборки PyTorch из исходников.

|---|---|---|---|---|
| 1 | `добавь нарзан` | Нарзан (56160) | ✓ | substring_p1 |
| 2 | `хочу сок` | Сок морковный (21101) | ✓ | substring_p2 |
| 3 | `положи нарзaн 2 шт` | Нарзан (56160) | ✓ | levenshtein |
| 4 | `творожная запеканка на завтрак` | Запеканка (69) | ✓ | substring_p1 |
| 5 | `дай мне кефир пожалуйста` | MISS | ✓ | — |

| 8 | `нaрзaн` (2 лат.) | Нарзан (56160) | ✗ | все мимо |

**Итог: 7/8 (87.5%)**

Промах на граничном случае: 2 опечатки (латинские `a`) в 6-символьном слове дают нормализованное расстояние 0.333 > порог 0.25.

### Trigram cosine — отдельный анализ

| Запрос | Результат | Similarity |
|---|---|---|
| `творожная запеканка` | Запеканка классическая | 0.900 |
| `запеканка творожная` | Запеканка классическая | 1.000 |
| `морковный сок детский` | Сок детский морковный | 0.798 |
| `вода минеральная` | MISS | <0.75 |
| `минералка` | MISS | <0.75 |

Trigram cosine отлично ловит перестановки слов, но бессилен против семантических совпадений (разные слова — один смысл). На практике этап 3 редко достигается, потому что substring (этап 1) с несколькими вариантами ключей ловит перестановки раньше.

### Формат prefs (v2)

```json
{
  "version": 2,
  "products": {
    "56160": {
      "name": "Вода минеральная 'Нарзан' природной газации, 1 л",
      "keys": ["нарзан"]
    },
    "21101": {
      "name": "Сок детский морковный с мякотью, 250 мл",
      "keys": ["морковный сок", "сок морковный"]
    },
    "69": {
      "name": "Запеканка классическая",
      "keys": ["запеканка", "запеканка творожная"]
    }
  }
}
```

**Изменения относительно v1:**
- Плоский `{key: {xml_id, name}}` → иерархический `{products: {id: {name, keys}}}`
- Один продукт = один `xml_id`, несколько `keys` (синонимов)
- Векторы не хранятся (trigram cosine вычисляет на лету)
- Автоматическая миграция v1→v2 при первом чтении

## 6. Известные ограничения

1. **Семантический матчинг.** `«вода минеральная»` → `«Нарзан»` не ловится ни одним из трёх этапов. Нужны эмбеддинги (sentence-transformers), которые не ставятся на aarch64/Android.

2. **Двойные опечатки.** `«нaрзaн»` (2 латинские буквы в 6-символьном слове) — distance 0.333 > порог 0.25. Можно поднять порог до 0.35 ценой потенциальных false positives.

3. **Склонения и падежи.** `«молока»` не матчится с ключом `«молоко»` через substring (разные окончания). Решение: добавлять все формы при сохранении (`«молоко»`, `«молока»`, `«молоку»`) или использовать стемминг.

4. **Нет pre-computed векторов.** Trigram cosine считает векторы на лету. Для <50 продуктов это микросекунды, но может быть узким местом при 1000+.

## 7. Возможные улучшения

| Идея | Сложность | Эффект |
|---|---|---|
| Стемминг/лемматизация (pymorphy3) | Средняя | Ловит падежи без доп. ключей |
| Pre-computed trigram vectors в prefs | Низкая | Микрооптимизация для больших prefs |
| Эмбеддинги через API (OpenAI) при наличии ключа | Низкая | Семантический матчинг |
| sentence-transformers при появлении aarch64 wheel | Низкая | Локальный семантический матчинг |
| Динамический порог Левенштейна (зависит от длины слова) | Низкая | Меньше граничных промахов |

## 8. Использование

### В production (через LLM + Hermes)

```python
# LLM вызывает execute_code:
import sys
sys.path.insert(0, "~/.hermes/skills/vkusvill-smart-cart/scripts")
from match import match_all

result = match_all("добавь нарзaн")
# → {"winner": {"stage": "levenshtein", "xml_id": 56160, ...}, "winner_stage": "levenshtein"}
```

```python
from embed import add_product
add_product(xml_id=12345, name="Молоко 3,2%, 1 л", keys=["молоко", "молоко 3.2%"])
```

