# Как AI-агент для заказа во ВкусВилл прошёл путь от Termux до одного HTML-файла — и чему меня это научило

В декабре прошлого года ВкусВилл [опубликовал на Хабре статью](https://habr.com/ru/companies/vkusvill/articles/981866/) про свой MCP-сервер. За прошедшие полгода вышло ещё несколько статей, которые описывали использование этого API — как работает сервер, как заставить AI-агента формировать заказ, — поэтому технические детали уже неплохо задокументированы.

Я хочу рассказать о другом: как система прошла эволюцию от AI-агента в Termux на Android до полностью автономного HTML5-файла. Это история не столько про конкретный API, сколько про эффективное внедрение AI, баланс между «умным» и «простым» решением, пользу экспериментов — и про те удивления, которые ждали меня по дороге.

---

## Этап 1: Hermes Agent в Termux на Android

Стартовая точка: **Hermes Agent**, развёрнутый в Termux на Android-телефоне. Достаточно дать агенту ссылку на статью про MCP-сервер ВкусВилл и попросить: «Собери корзину: нарзан, йогурт, мандарины». Агент сам вызывает API, находит товары и формирует ссылку на корзину.

Работает. Удобно? Почти. **Цена:** около **\$0,50 за одну корзину** — каждый вызов MCP требовал полного цикла «поиск → резолвинг → корзина», и каждый шаг тратил токены.

Для демонстрации «смотри, AI может заказывать продукты» — отлично. Для регулярного использования — дороговато.

## Этап 2: Оптимизация (оптимизация обошлась дороже, чем сама задача)

Начал с двух направлений:

### а) Смена модели

Переключился с дорогой модели на более дешёвую. Качество матчинга просело незначительно, а цена токенов упала радикально.

### б) Локальный словарь частых покупок

Основной трюк: вместо того чтобы гонять каждый запрос через MCP, я собрал словарь из ~50 часто заказываемых товаров прямо на телефоне. Теперь агент сначала ищет в локальном словаре (alias-матчинг, substring, триграммы — три эшелона), и только если не находит — идёт в MCP.

Агент на этапе обсуждения архитектуры предложил **пять разных вариантов** реализации. Без должного опыта это непростая развилка: локальный JS, Python-скрипт, встройка в навык агента, SQLite, серверный прокси. Выбрал локальный матчинг внутри скилла Hermes — минимальные накладные расходы.

**Результат:** стоимость упала с \$0,50 до **\$0,04 за корзину**. Затраты на токены в процессе оптимизации — около **\$6**.

> Скриншоты: смена LLM-модели, локальный словарь, стоимость после оптимизации

## Этап 3: «Отдай навык другому агенту» — Android → Windows

Когда скилл заработал стабильно, я перенёс его на другую машину (Windows Surface). Hermes Agent запущен на Windows, скилл скопирован — и всё заработало **без шероховатостей**. Никакой магии: навык — это просто набор инструкций и скриптов, не привязанных к платформе.

Это важный момент: AI-агент — не «приложение», которое нужно портировать. Это скорее спецификация поведения, которая воспроизводится на любой платформе, где запущен агент.

## Этап 4: Чтобы пользовались другие

### Вариант А — Сервер

Стандартный подход: Flask + Gunicorn + Nginx, API для матчинга и создания корзины, деплой на VPS.

Работает, но:
- Нужен сервер (VPS, домен, Let's Encrypt, мониторинг)
- Нужно обслуживать: логи, health check'и, ротация, бэкапы
- Для «попробовать один раз» — слишком высокий порог входа

### Вариант Б — Один HTML5-файл

Самый быстрый и дешёвый способ. Что получилось:

- **Один HTML-файл** (46 КБ), открывается в браузере телефона или ПК
- **119 товаров** в 12 категориях, **106 алиасов** для быстрого поиска
- **Прямой вызов MCP** из браузера — кнопка «Собрать корзину» шлёт JSON-RPC на `mcp001.vkusvill.ru`, никакой сервер не нужен
- **Быстрый ввод:** строка поиска принимает текст без запятых — `нарзан йогурт мандарин` — трёхэтапный JS-матчинг (alias → substring → word+bigram)
- **PWA:** устанавливается на домашний экран, Service Worker кэширует каталог — работает офлайн (кроме создания корзины — там нужен MCP)
- **Тёмная тема, адаптивная вёрстка,** копирование ссылки в буфер

Живой сайт: [vv.vedomir.ru/select/](https://vv.vedomir.ru/select/) — открытый доступ, без пароля. Весь код — на [GitHub](https://github.com/volgarevmaxim-bit/vkusvill-html-zakas-order).

## Мои удивления

### 1. Окружающие не разделяют энтузиазм

Я был в восторге: AI формирует заказ, экономит время, будущее наступило! Реакция друзей и семьи: «Обычный способ — открыть сайт и нажать несколько кнопок — удобнее и быстрее. Зачем всё это?»

И знаете, они правы. Для человека, который заказывает 3–5 позиций раз в неделю, традиционный интерфейс действительно проще. AI-агент выигрывает, когда заказ сложный, или когда ты делаешь это голосом за рулём, или когда у тебя 50+ позиций. Но это — нишевый сценарий, а не массовый.

**Вывод:** AI-решение не обязательно должно быть «лучше для всех». Оно должно решать конкретную боль конкретного пользователя. И честно признавать, когда боль недостаточна для оправдания сложности.

### 2. Агента пришлось уговаривать делать HTML5

Когда я сказал агенту: «Сделай автономный HTML-файл, который вызывает MCP ВкусВилл напрямую из браузера», — он начал рассказывать, почему это невозможно:

- «Браузер не может слать JSON-RPC на чужой домен — CORS заблокирует»
- «Нужен серверный прокси»
- «MCP — это серверный протокол, не для браузера»

Пришлось настоять: «Проверь CORS-заголовки MCP-сервера». Оказалось, `mcp001.vkusvill.ru` возвращает `Access-Control-Allow-Origin: *`. MCP ВкусВилл **разрешает** браузерные запросы. Агент признал: «Вы правы, прямой вызов возможен».

Это характерная черта современных LLM: они хорошо знают «общие правила» (CORS блокирует, MCP — серверный протокол), но не проверяют конкретные реализации. Правило != реальность. Иногда нужно спорить с агентом — и побеждать.

### 3. Сервер ВкусВилл отдаёт картинки в base64

Когда делал отображение товаров с фотографиями, обнаружил, что MCP возвращает изображения **в base64 внутри JSON**. Это необычно для публичного API. Плюсы: картинка всегда доступна, не зависит от CDN, не нужно управлять URL. Минусы: JSON-ответы становятся тяжёлыми, а в браузере нужно вставлять `data:image/jpeg;base64,...`.

## Технические уроки (выборочно)

За 4 этапа и 19 коммитов накопилось 17 задокументированных уроков. Вот самые важные:

### MCP CORS: `Access-Control-Allow-Origin: *` — это шлюз в браузер

Ключевое открытие: MCP-сервер ВкусВилл разрешает кросс-доменные запросы. Это позволило убрать серверную прокси-прослойку и сделать один HTML-файл полностью автономным. Всегда проверяйте реальные заголовки ответа — спецификации могут говорить одно, а реальность другое.

### Локальный матчинг дешевле AI на три порядка

Три эшелона матчинга (alias → substring → word+bigram), реализованные на чистом JS, стоят **ноль токенов** и работают мгновенно. AI нужен только для одной вещи: вызвать `vkusvill_cart_link_create` с правильными xml_id. Всё остальное — детерминированная логика.

### Python triple-quoted strings ≠ JavaScript strings

Когда JS-код вшит в Python через `"""..."""`, бэкслеш-последовательности интерпретируются Python-парсером. `'\\n'` становится literal newline, ломая JS-синтаксис. Решение: `String.fromCharCode(10)` в JS вместо `'\n'`, когда код живёт внутри Python-строки.

### Service Worker требует bump'а версии при каждом деплое

После деплоя исправленного `index.html` браузер продолжал показывать старую версию — Service Worker с cache-first стратегией отдавал закэшированную копию. `curl` на сервере показывал новый файл, пользователь видел старый баг. Решение: bump `CACHE = 'vkusvill-vN'` в `sw.js` при каждом деплое.

### User-Agent имеет значение для WAF

Qrator блокирует запросы с дефолтным `User-Agent: Python-urllib/3.x`. Кастомный `User-Agent: VkusVill-Cart-Server/1.0` — дёшево и работает.

### Тестировать в браузере, а не только curl

`curl` подтверждает, что API жив, но не ловит битый JavaScript. После деплоя открывать страницу в браузере и нажимать кнопку — только так видно, что скрипт загрузился и работает.

## Заключение: AI + традиционный софт — правильный гибрид

Главный вывод из этого проекта: **чистый AI-агент — перебор для рутинной задачи**. Но AI как «клей» между пользователем и традиционным софтом — мощнейший паттерн.

В финальной версии AI делает ровно одну вещь: принимает описание продуктов на естественном языке, резолвит их в xml_id и вызывает `vkusvill_cart_link_create`. Всё остальное — матчинг, кэширование, UI, офлайн-режим — делает обычный код. Стоимость: \$0,04 за корзину. Скорость: мгновенно.

Я убеждён, что такие «гибридные» проекты до сих пор недооценены. Порог входа низкий: не нужно разворачивать K8s-кластер или тюнить LoRA. Достаточно одного HTML-файла и доступа к API. Если вы ещё не пробовали — очень советую. Удивления гарантированы.
